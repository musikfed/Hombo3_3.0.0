# PegineLab — архитектура лаборатории и контракт разработки / Lab architecture

> Снимок конфигурации: **2026-11-01**. Данные оборудования и сети сообщены владельцем. Это **описание целевой и заявленной конфигурации**, а не результат автоматической проверки доступности узлов. Файл намеренно синхронизирован в `musikfed/wificam_T23N` и `musikfed/Hombo3_3.0.0`; изменяя топологию, обновляйте обе копии RU/EN одновременно.
>
> **Без секретов:** не добавлять в GitHub публичный IP, закрытые ключи, `privkey.pem`, токены, пароли, конфигурации VPN с секретами, дампы TLS/SSH и приватный `.env`.

## Назначение и границы проектов

**WIFICAM T23N:** независимая прошивка IP Wi-Fi камеры на SD-карте (Thingino/Raptor, MIPS, T23N), локальный PegineLab Web UI, RTSP/JPEG, ONVIF/PTZ при наличии аппаратной поддержки, микрофон/динамик при проверке соответствующего аудиотракта, обязательный SSH для восстановления. **Сборка и запись карты выполняются в Ubuntu 24.04 под WSL на Acer**. Камере не поручаются тяжёлые LLM.

**Hombo3 3.0:** интерфейс и управляющий backend робота запускаются **нативно в Windows 11 Pro на Acer Swift 3**, а не внутри WSL. Низкоуровневая безопасность шасси и моторы робота остаются на ESP32-S3. Acer объединяет видеокадры T23N, звук, YOLO/VectorProbe, локальное управление и вызовы внешних LLM.

**Лаборатория:** мощная LLM-инференция — CORE `.100` (RTX 3060), доступ к нему через доверенную локальную сеть или защищённый VPN; DEXP `.109` выполняет роль внешнего входного шлюза, а Ardor `.103` — дополнительная графическая рабочая станция. Внешнее облако производителя IP-камеры **не требуется**.

## Карта инфраструктуры

```text
                     ИНТЕРНЕТ
           белый статический IP + купленный TLS/домен
                      │ (100 Мбит/с WAN)
                Tenda TX12 (роутер)
          NAT, Wi-Fi, WireGuard/OpenVPN-клиент
                      │
        ┌─────────────┴──────────────────────┐
        │          локальная LAN             │
        │    гигабитная коммутация/хабы      │
        │                                    │
        ├── .109  DEXP N100 / Ubuntu         │
        │         Docker Compose / AmneziaWG │
        │         2FA/CI/CD / edge gateway   │
        │         VPN ↔ защищённый доступ    │
        │                                    │
        ├── .100  Huananzhi X79 / Ubuntu     │
        │         2×Xeon / RTX3060 / CORE    │
        │         LLM/Ollama inference       │
        │                                    │
        ├── .103  Ardor / Windows 11         │
        │         Ryzen 5 5600 / RX7600XT    │
        │         GRAPHICS workstation       │
        │                                    │
        ├── .101  Tenda E205, управляемый    │
        │         коммутатор (связь Ardor)   │
        │                                    │
        ├── Acer Swift 3 / Win 11 Pro        │
        │         HOMBO3 control center      │
        │         WSL Ubuntu 24.04 (D:)      │
        │         SD firmware build only     │
        │                                    │
        ├── T23N Wi-Fi camera / Thingino     │
        │         пример проверенного IP:    │
        │         192.168.1.55               │
        │                                    │
        └── Hombo3 ESP32-S3 / robot control  │
                 (адрес проверять отдельно)

  Cisco Catalyst 3250 — учебный, в обычной схеме выключен.
  Умная розетка / Wake-on-LAN — включение совместимых ПК по необходимости.
```

> Обозначения `.100`, `.101`, `.103`, `.109` — **суффиксы LAN-адресов** из описания, не самостоятельные DNS-имена. Полная подсеть, DHCP/reservation, точный Windows-IP Acer, публичный IPv4 и маршруты VPN требуют отдельной инвентаризации. Не считать `192.168.1.0/24` для всех устройств подтверждённой схемой только по одному адресу камеры.

**Дополнения к железу:** CORE — БП 650 Вт Bronze, отдельное нижнее размещение БП и дополнительное охлаждение корпуса/CPU. ## Разделение инструментов: Windows / WSL / Linux server

### Acer — Windows 11 Pro: Hombo3

Доступные в PowerShell версии на **2026-11-01**:

```text
py -V:3.14   → Python 3.14.4 (текущая версия по умолчанию)
py -V:3.13   → Python 3.13.13
py -V:3.12   → Python 3.12.9
uv --version → 0.11.15 (Windows x86_64)
```

В репозитории Hombo3 лежит `.python-version = 3.13`. **Для Hombo3 закрепляем Python 3.13**, не полагаемся на голый `py`, который сейчас выбирает 3.14.

```powershell
# Windows PowerShell, в рабочем checkout Hombo3 (путь зависит от ПК)
cd <PATH-TO-Hombo3_3.0.0>
py -3.13 --version
uv venv --python 3.13 .venv
uv pip install --python .venv\Scripts\python.exe -r backend\requirements.txt
.\.venv\Scripts\python.exe backend\run.py
# UI разрабатывается отдельно через npm в frontend/ (см. проект)
```

`APP_HOST/APP_PORT` и интеграцию камеры/CORE задавать в локальном `.env` без публикации секретов. Для вызовов Ollama/LLM предпочтителен локальный URL узла `.100` внутри LAN либо адрес в VPN; **не открывать Ollama TCP 11434 напрямую в Интернет**. Большая часть YOLO/VectorProbe обработки остаётся на Acer; тяжёлую LLM — перенести на RTX 3060 узел по доверенной сети.

Рабочие Linux-пути, использованные при предыдущей сборке:

```bash
cd ~/myipcam/wificam_T23N
git switch mymarrchWFcam
git pull --ff-only origin mymarrchWFcam
# Thingino checkout: ~/myipcam/thingino-firmware
# CAMERA=galayou_g2_t23n_sc2336_atbm6012bx
THINGINO_FAST=1 PUBLISH=1 sh scripts/build_thingino_wificam_image.sh
```

Не путать размещение **диска виртуальной машины на Windows D:** с Linux-путём исходников `/home/obzor/myipcam/...`. Важные I/O-intensive сборки лучше оставлять внутри Linux ext4, а не в `/mnt/d`.

Готовый образ: `Thingino/thingino-t23-sd.bin`; запись **целого SD образа от LBA0**, без дополнительных `dd seek/skip`, только после проверки физического кардридера. Realtek `0bda:0177` в ранее отработанном сценарии пробрасывался **из Windows PowerShell** через `usbipd attach --wsl --busid 3-2`; BUSID и имя `/dev/sdX` перепроверять при каждом подключении. Не переписывать другие диски, особенно системный WSL `/dev/sdd`. Прошивка `0.1_test` — сохранённый boot baseline, новые CGI/PTZ/скоростные правки требуют нового SD образа и аппаратной приёмки.

### CORE .100 — Ubuntu Server 24.04: LLM

Сообщённые версии:

```text
Python 3.12.3 (GCC 13.3.0)
uv 0.12.0 (x86_64-unknown-linux-gnu)
```

Только этот узел содержит основную RTX 3060 12 ГБ для тяжёлой инференции; задачи LLM/семантического анализа отдавать сюда, **не на камеру**. Управление энергопитанием и Wake-on-LAN — часть планируемого сценария по запросу, а не повод выключать сервер во время действующего сеанса.

## Переходы данных и права управления

```text
T23N SC2336 -> Raptor RTSP/JPEG -> Wi-Fi/LAN -> Acer Hombo3 CameraHub
                                         -> YOLO/VectorProbe / зрение
                                         -> нормализованные наблюдения
                                         -> GPU CORE .100 (LLM/Ollama)
                                         <- высокоуровневое решение / ответ
Acer Hombo3 -> ESP32-S3 (ограниченные команды движения, safety на контроллере)
Acer Hombo3 -> T23N ONVIF/PTZ (калиброванный реверс осей, STOP)
Acer Hombo3 -> T23N SSH -> Raptor play/rac (необязательный динамик TTS)
T23N mic -> RTSP audio track -> Acer (STT после отдельной интеграции)
Внешний пользователь -> TLS/2FA и AmneziaWG на .109 -> разрешённые LAN endpoints
```

**Дизайн-принципы:**

1. **Local-first, SD-first:** IP-камера продолжает работать в локальной сети даже при отключении внешнего Интернета и облака производителя. SSH/Dropbear на ней не убирать.
2. **Acer — оркестратор, не GPU-сервер:** объединяет интерфейс, робота, камеру, локальные быстродействующие реакции, маршрутизацию аудио/видео; дорогие LLM задачи — CORE `.100`.
3. **Минимальная задержка:** Raptor RTSP/substream или долгоживущий MJPEG вместо постоянных JPEG-запросов; последний кадр вместо очереди; низкие потери управления PTZ. Эффективные FPS/RTT измерять, не заявлять до теста.
4. **Функции по наличию железа:** PTZ, автофокус, оптический zoom, микрофон и динамик — включать по результату реального capability/device теста. Цифровой zoom отдельно от оптического.
5. **Границы доверия:** внешние подключения только через аутентифицированный TLS/2FA/VPN edge; проброс отдельных портов по allowlist, а не автоматический прямой доступ ко всем узлам. Ключи/пароли в секрет-хранилище и локальных `.env`; не в GitHub.
6. **Безопасность робота:** LLM выдаёт предложения/высокоуровневые команды; ограничение моторного действия и аварийная остановка — локально ESP32. Не выполнять произвольные команды shell из ответов модели.
7. **Энергосбережение:** .100 и .103 могут пробуждаться по сети/питанию при наличии аппаратно настроенного WOL, но не выключаться, пока есть активная работа.
8. **Разграничение работы:** GitHub — код, инструкции, hashes, tags/releases. Реальный бинарный SD, сетевой сертификат, доступность VPN и аудио/PTZ проверяются отдельно.

## Домены, сеть и неизвестные параметры

- Интернет: **100 Мбит/с**, стоимость по сообщению владельца **655 ₽/мес**, белый статический адрес. Сам адрес сюда не записан.
- Основной роутер: **Tenda TX12**, имеются WireGuard/OpenVPN клиентские возможности и старый PPTP-сервер; старый PPTP **не рекомендован** для новой удалённой инфраструктуры.
- VPN/edge: **DEXP N100 .109**, контейнер AmneziaWG server, Docker Compose, 2FA и CI/CD.
- Публичное имя, названное владельцем: **peginelab.ru** (покупной SSL, почта) и **peginelab.com** (пометка рядом с DEXP). **Принадлежность и роль каждого домена/цепочки сертификатов не проверялись**; до публикации приложений необходимо проверить DNS, SAN, владельца и маршрутизацию.
- Управляемый коммутатор **Tenda E205 .101** связывает Ardor; остальная проводная LAN через гигабитные хабы. Cisco Catalyst 3250 пока выключен.
- Нельзя помещать `fullchain.pem` и особенно `privkey.pem` в Git. Сертификаты должны обновляться на назначенном TLS-терминаторе.
- Неизвестные поля для будущей схемы: точные адреса Acer/ESP32, маска подсети/VLAN, WAN адрес, DNS/CNAME, реальный VPN CIDR, топология NAT, набор открытых портов и распределение TLS termination. Заполнять только после проверки в локальной сети.
