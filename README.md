# Hombo3 3.0 · Robot Control Center

Hombo3 — отдельная система домашнего робота на **ESP32-S3-DevKitC-1 N16R8 (16 MB Flash + 8 MB Octal PSRAM)**. Ghost32 остаётся универсальной лабораторией/прошивальщиком плат. Hombo3 отвечает за конкретную машинку: шасси, дальномеры, ONVIF-камеру, голос, VectorProbe, локальное зрение, Ollama/LLM, RAG+Graph, MCP и OTA.

## Зафиксированный аппаратный baseline 3.0

Пины ниже считаются **монтажным контрактом** проекта. После пайки они меняются только новой ревизией документации и `board_config.py`.

| Узел | GPIO ESP32-S3 | Подключение |
|---|---:|---|
| TB6612-L IN1 | 18 | AIN1 + BIN1 левого драйвера |
| TB6612-L IN2 | 17 | AIN2 + BIN2 |
| TB6612-L PWM | 14 | PWMA + PWMB |
| TB6612-R IN1 | 21 | AIN1 + BIN1 правого драйвера |
| TB6612-R IN2 | 10 | AIN2 + BIN2 |
| TB6612-R PWM | 12 | PWMA + PWMB |
| STBY | 40 | STBY обоих TB6612 |
| HC-SR04 front | 1 / 7 | TRIG / ECHO; ECHO через 1k/2k |
| HC-SR04 rear | 6 / 5 | TRIG / ECHO; ECHO через 1k/2k |
| HC-SR04 head | 4 / 16 | TRIG / ECHO; ECHO через 1k/2k |
| VL53L0X | 8 / 9 | SDA / SCL |
| MAX98357A | 11 / 13 / **15** | BCLK / LRC / DIN |
| АКБ 2S2P | **2** | ADC1_CH1 через делитель **3k/1k** |

**Единственное намеренное изменение относительно старой UNO-схемы:** MAX98357A DIN перенесён с GPIO2 на GPIO15, а GPIO2 отдан под измерение аккумулятора. GPIO3 не используется для battery sense, потому что это strapping pin ESP32-S3. GPIO35..37 не используем в N16R8 из-за Octal memory.

### Делители — не перепутать

HC-SR04 ECHO (каждый из трёх):

```text
ECHO 5V ── 1k ──●── GPIO7 / GPIO5 / GPIO16
                 │
                 2k
                 │
                GND
```

АКБ 2S2P, максимум 8.4 В:

```text
BMS P+ ── 2k ── 1k ──●── GPIO2 / ADC1_CH1
                       │
                       1k
                       │
BMS P- / общий GND ────┘
```

Это коэффициент 4:1: 8.4 В → примерно 2.10 В на ADC. Никакие 3.3 В на этот делитель не подаются.

## Два TB6612 — по одному на борт

- `TB6612-L`: канал A → передний левый мотор FL, канал B → задний левый BL. Его A/B входы управления запараллелены.
- `TB6612-R`: канал A → передний правый FR, канал B → задний правый BR. Его A/B входы управления запараллелены.
- Если один мотор на борту вращается наоборот, меняется **полярность только этого мотора**, а не общая логика IN1/IN2.

## Сеть и вычислительные роли

```text
REGGO camera/mic --ONVIF/RTSP--┐
ESP32-S3 --HTTP/WS/PCM/Wi-Fi---+--> Acer / Hombo3 Control Center
                               |       |- FastAPI + React
                               |       |- YOLO / classifier
                               |       |- VectorProbe + map
                               |       |- STT/TTS + RAG/Graph + MCP
                               |       `- agent/safety orchestration
                               |
                               `-- secure LAN/VPN/HTTPS --> Huananzhi / Ollama / Hermes or another LLM
```

ESP32 и камера наружу напрямую не публикуются. Если LLM-сервер доступен через белый IP, доступ оформляется через защищённый канал; незакрытый Ollama `:11434` в Интернет не выставляется.

## Hombo VectorProbe

VectorProbe объединяет:

1. **Reference Map** — нарисованные оператором стены, проходы, комнаты, мебель-якоря и зарядная зона.
2. **Vector Map** — память реальных HC-SR04/ToF лучей.
3. **Live Pose/Map** — текущая дрейфующая оценка x/y/heading.
4. **Semantic Inventory** — распознанные предметы и устойчивые ориентиры.
5. **Dynamic Layer** — люди, кошки и временные предметы.
6. **Robot Track/Route** — история движения и запланированный путь.

Дрейфующая поза не переписывает эталонную стену. При совпадении нескольких дальномерных лучей со стенами VectorProbe ищет локальную коррекцию позиции/курса. Камера и классификатор дают семантические якоря. Временный предмет остаётся временным, пока оператор явно не закрепит его как постоянный.

## Аккумулятор и возврат к зарядке

Базовая сборка не требует отдельного fuel-gauge: ESP32 измеряет напряжение 2S2P через GPIO2, а Acer фильтрует историю и оценивает SOC/тренд зарядки. Пороговая политика по умолчанию:

- ≤25% — планировать зарядку;
- ≤15% — возвращаться к зарядной зоне;
- ≤8% — критический режим.

ETA зарядки по одному напряжению является оценкой. Позже INA226/fuel-gauge можно добавить по I²C, не меняя контракт веб-морды.

## Обновление

Первое развёртывание на уже работающий Ghost32 допускается через `MIGRATE_FROM_GHOST32.ps1`. После этого обычные обновления прикладного runtime идут **по текущей Wi-Fi сети** с backup/rollback. Primary Wi-Fi → Backup Wi-Fi → `Hombo3-Recovery-XXXX`. USB/COM остаётся аварийным путём.

Запуск на Acer:

```powershell
.\SETUP.cmd
.\START_HOMBO3.cmd
```

Веб-морда: `http://127.0.0.1:8000`.

## Безопасность

LLM не получает сырого GPIO. Агент работает через семантические MCP-tools, а ESP32 сохраняет локальный watchdog, TTL-команд, obstacle-stop и аварийный STOP. Планировщик VectorProbe может строить маршрут, но ходовой исполнитель допускается в автономный режим только после реального стендового теста направлений моторов, торможения и датчиков.

Подробная пайка: `docs/HOMBO3_PINOUT_QUICK_RU.md` и `docs/HARDWARE_BASELINE_RU.md`.
