# Code review исходного `robot_full_package_v1.1.zip`

## 1. Критическая ошибка: модель двух TB6612 не соответствовала железу

В исходной прошивке было прямо зафиксировано:

```text
A channels on BOTH drivers = left side
B channels on BOTH drivers = right side
```

и UI повторял ту же модель: `A/PWMA обоих TB6612 = левый борт`, `B/PWMB обоих = правый борт`.

Фактическая конструкция, подтверждённая стендовым тестом, другая:

```text
TB6612-L = FL + BL
TB6612-R = FR + BR
```

Поэтому общий A-сигнал включал по одному мотору на каждом драйвере и получалась диагональ. Общий B-сигнал давал вторую диагональ.

Это нельзя исправить одной перестановкой `left/right` в Python: при старой электрической группировке сигналы уже объединены не по тем узлам. В RC1 сохранены шесть управляющих GPIO, но fan-out перенесён внутрь каждого драйвера: A+B левого TB6612 получают LEFT-команду, A+B правого — RIGHT-команду.

## 2. Архив v1.1 был не единым релизом, а накопленным рабочим деревом

Текущие файлы совпадали с разными историческими патчами:

- часть backend/frontend/firmware — v0.4;
- управление/камера — v0.4.2;
- `main.py` — v0.4.3;
- persistence UI — v0.4.4;
- `memory.py` и `ollama_client.py` — v0.4.5.

Это нормально как результат разработки, но плохо как точка восстановления: невозможно понять, какие патчи ставить и в каком порядке. RC1 берёт именно текущие файлы как итоговое состояние и удаляет ladder патчей.

## 3. Версии расходились

В исходном архиве одновременно были:

- имя архива `v1.1`;
- README/React package `0.2.0`;
- FastAPI `0.4.0`.

В RC1 используется одна версия: `1.2.0-rc1`.

## 4. В исходный архив попали приватные настройки

- корневой `.env` содержал реальные локальные параметры/учётные данные;
- Wi-Fi SSID/password были записаны непосредственно в `.ino`.

RC1 не содержит `.env` и реального Wi-Fi пароля. Для ESP32 добавлен `secrets.h.example`.

## 5. 127 МБ архива были runtime-данными, а не исходниками

Основные объёмы исходного v1.1:

- `data/robot.sqlite3` ≈ 72.6 МБ;
- `data/logs/behavior_dataset.jsonl` ≈ 48.8 МБ;
- `yolo11n.pt` ≈ 5.4 МБ.

SQLite и накопленный dataset исключены из RC1. YOLO11n оставлен как часть рабочего комплекта.

## 6. Зависимости были неоднозначны

Корневой `requirements.txt` не относился к backend и содержал единственную UTF-16 запись `uv==0.11.15`; реальный backend использовал `backend/requirements.txt`.

Также текущий `vision.py` импортирует `ultralytics`, но пакет отсутствовал в основном backend requirements и раньше доставлялся одним из patch-installers. В RC1 `ultralytics` добавлен в основной requirements.

Frontend теперь устанавливается через `npm ci` по `package-lock.json`.

Точный Python lock восстановить из архива v1.1 невозможно, потому что `.venv` был правильно исключён, а исторический requirements содержал диапазоны. После первого подтверждённого запуска RC1 можно выполнить `scripts/freeze_python_lock.ps1`; последующие установки автоматически предпочитают `backend/requirements.lock.txt`.

## 7. `.env.example` отстал от кода

`Settings` уже содержал параметры low-latency camera и local YOLO, которых не было в `.env.example`. RC1 синхронизирует шаблон со всеми текущими настройками.

## 8. В релизе оставались резервные копии и patch history

Были `.bak_*`, `__pycache__`, `_patch_backups`, `paches-history`. Они полезны во время разработки, но не должны быть частью базового релиза. В RC1 они удалены и добавлен `.gitignore`, чтобы не возвращались случайно.
